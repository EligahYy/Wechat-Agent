# 交互与视觉实施方案

更新：2026-11-13（北京时间）。范围遵循 [产品方案](PRODUCT_DESIGN.md)。最新细节以本文为准，原型用于比对效果，不把原型里的演示逻辑直接当生产实现。

## 1. 信息架构

全局只有 **工作台、设置** 两个入口。桌面设计，最小画布 1120px，不做移动端布局。

工作台内有“商家档案”“全部联系人”。不设今日、独立任务页、白名单、客户侧栏或一长列待确认项。

## 2. 工作台

### 2.1 顶部与整理进度

右上角主操作“同步并整理”，次操作“整理记录”；不再并列独立的“刷新联系人”。同步本身先刷新联系人／会话资料并拉取最新消息，再模型整理并更新商家资料。运行时主操作显示“停止本次”，停止且确有剩余时显示“继续本次”。已完成不显示继续。

顶部状态条说明当前实际阶段、完成数量和异常。空闲时显示每日整理时间；来源未连接时明确未连接，不把示例／缓存判断当成真实查询。

同步、解析、整理分别显示实际阶段和结果。批量部分失败时保留完成数量并提供失败目标的重试，不统一显示“全部完成”；无新增聊天但还有未处理资料时说明仍待整理。运行中断显示可恢复状态，空闲时不显示幽灵运行。

批量进度按客户汇总，单客户同步也进入同一执行层。进度面板可查看、停止、继续或重试；没有运行中的任务时不展示“暂停分析”。

### 2.2 商家档案列表

统一列：联系人、货品与路线、当前沟通、资料更新、查看入口。包含已确认商家尚未建档的行；服务商、平台和待识别不在这里显示。

搜索框统一提示“搜索姓名或备注”，只匹配当前可用昵称／备注和页面实际显示的姓名。资料状态筛选为全部资料、待更新、待整理；暂无资料在行内说明，未暴露的失败不能被筛选吞掉。

“整理不完整”及来源缺口是完整性说明，放在对应行／资料旁，不作为新的沟通状态标签。只展示有业务含义的缺口及重试入口，不恢复已删除的侧栏统计。

每页最多 20 位。按最近业务沟通时间排序；未整理者使用最近归档时间，不把整理运行时间冒充客户沟通时间。

### 2.3 全部联系人

身份筛选：全部、商家、服务商、平台、待识别。搜索规则与商家页一致：仅姓名／备注，忽略首尾空格，按字面子串匹配；不匹配wxid、来源群名或未展示的历史别名。群名片只有实际用于补位显示时才作为姓名匹配，仍保留来源标记，不据此确认真实身份。

勾选范围明确为本页或已选具体联系人，不自动选中未展示记录。勾选显示选中人数、“设置身份”和“清空”；取消最后一人时平滑收起。多选期间换页保留已选联系人，切换工作台页签清空选择。

勾选只更新 checkbox、计数和选中态，不重建列表行。表头支持部分选中态。取消或清空后键盘焦点落回可操作控件。

## 3. 客户详情弹窗

### 3.1 统一联系人头部

头像放在顶部姓名左侧。姓名旁显示可点击修改的身份标签与“复制微信名称”图标，wxid 作为弱化标识放在下一行。右侧为“同步并整理此客户”和关闭；非商家显示“同步该联系人消息”，不执行模型整理。

姓名和身份只显示一次。移除副标题中的推测公司名、英文别名和业务类目堆叠。复制内容来自微信名称，不能复制 wxid 或模型猜名代替。

客户详情在头部下方固定显示该账号、该客户的同步／整理进度、会话完成数、读取页数和最终结果；可查看详情或停止。正在处理时禁用重复提交；别人的任务不冒充本客户进度。提交／轮询错误显示在当前详情内，完成同步不等于完成模型整理。

商家／全部联系人均可打开联系人详情。非商家保留头部、身份管理、同步和沟通原文，不生成货品、物流及备货档案；切换为商家后才进入待整理。姓名、身份和复制入口仍只在头部出现一次。

**详情无侧栏**，不再单独展示来源定位标签、覆盖数量等附属统计。具体来源通过资料卡和原文查看，接入缺口放到设置／相应资料旁。

### 3.2 三个页签

| 页签     | 展示                                               |
| -------- | -------------------------------------------------- |
| 资料概览 | 当前摘要与状态；整合的货品概况卡、物流需求卡       |
| 备货记录 | 每批进度、货品货量、路线、单号及来源；允许录入单号 |
| 沟通原文 | 按时间浏览真实对话、回复和附件；支持搜索           |

顶部状态只展示有依据的沟通标签。未知留具体缺口，不放一段“不能判断任何事”的通用说明。

### 3.3 资料卡

货品和物流各用一张完整卡，不把每个字段拆成独立小卡。

卡片内部用分区标题、重点摘要、对齐的“字段—内容”行及少量分隔线。资料足够时直接说清货品、路线和当前需求；缺失字段明确列出。

每卡底部只保留“查看来源”“编辑资料”。人工补充单独标记；历史批次与当前需求不混为一个永久属性。

### 3.4 来源面板

按字段展示归纳结论与关联原文，可展开／收起；原文含真实发送人、身份、时间、会话及附件位置。

展开、收起均有动画；连续反向点击从当前高度接续，不等上一段结束，不产生错误最终状态。原文保持只读，编辑归纳内容不改写聊天。

## 4. 编辑与手动补充

### 4.1 分组

货品：货品信息、属性与货量、补充资料。

物流：路线与目的地、运输与服务、费用与关注、补充资料。

分组标题高于字段标签，不能缩成小号灰色说明。双列布局，仓库等长字段跨列；短字段单行，描述按内容增高。标题和操作栏固定，内容区独立滚动。

未修改时保存禁用。错误在相关字段下展示，不让浏览器英文气泡替代本地校验。保存后保留人工修改标记，焦点回到对应编辑入口。

身份或资料被其他操作更新时，保存必须检测版本冲突，保留当前填写内容并提供重新载入／核对；不能以“保存成功”覆盖刚生成的新内容。手动改值不改写原文，原模型值和修改记录仍可核对。

### 4.2 补充资料

允许填写固定模板没有覆盖的信息，作为人工备注保存，可编辑或清空。首版不做自定义字段管理器，不把人工备注冒充模型结论或原文。

### 4.3 单号录入

使用同一多行填写组件，每行一个单号，自动增高、去重保存。空值和超长值就近报错。保存后显示单号，不自动将批次变成已走货。

## 5. 设置

设置分为本机数据与模型、每日整理、外观三个区。仅显示能帮助操作或排错的信息，删除通用解释性标语。

- 来源：工作账号、wx-cli 连接、最近成功同步、来源缺口和重试；手动导入唯一入口。
- 模型：实际可用模型 ID、连接状态、配置状态和简明错误。前端不保留明文密钥。
- 每日整理：开关及开始时间。外观：跟随系统／浅色／深色。

模型配置包括实际 API 地址、model ID 和后端保存的凭据状态；界面只显示密钥是否已配置。连接测试使用明确操作，并区分鉴权、模型不可用、网络错误与结构化输出不支持。

模型区的维护入口提供“重新整理”，仅用于显式复算：选单客户或商家范围，展示数量和所用模型／策略版本，开始后复用现有进度与停止控制。它不重新读取微信，也不另建任务页面。切换模型不自动给全体客户发请求。

### 5.1 时间选择：单一完整控件

行内只放一个时间输入组件：**08:30 + 内嵌时钟入口**，不在旁边另摆时区文字。

- 点击时钟打开玻璃面板，小时和分钟分列选择，使用 24 小时格式。
- 时区收在面板内部的标题区域，固定“北京时间”，不再参与输入框旁的排版。
- 支持直接键入，例如 9:05 规范为 09:05；无效时间保留供修正并就近报错，不覆盖已保存值。
- 面板选择先改草稿，点击“应用”后保存；取消、Escape 或点击外部不保存草稿。
- Arrow／Home／End 选择，Enter 确认选项；关闭后焦点回到时钟。选项滚动不带动整个页面。
- 每日开关关闭时，时间和选择入口一起禁用。
- 面板自动避开屏幕边缘；开启与收起有轻微过渡。

## 6. 视觉规范

使用 Apple 系统字体，主色 #0066cc；浅色背景 #f5f5f7、正文 #1d1d1f。深色背景、卡片、文字、填写框和弹窗必须一起切换，不能出现深色文字配浅色页面的混用。

玻璃材质用于导航、页签、浮层和操作层；资料正文保持清晰的实色背景。主导航保留，客户详情侧栏移除。

### 6.1 字号与标签

| 用途                         | 字号 / 字重  |
| ---------------------------- | ------------ |
| 页面主标题                   | 36 / 600     |
| 客户弹窗、编辑弹窗标题       | 24、22 / 600 |
| 资料分区标题                 | 18 / 600     |
| 编辑分组标题                 | 16 / 600     |
| 正文与填写内容               | 14 / 400     |
| 字段标签和常规操作           | 13 / 400–500 |
| 辅助信息、身份／沟通状态标签 | 12 / 400–500 |
| 原文紧凑身份标签、内部 ID    | 11           |

常规身份／状态标签高度 28px，原文紧凑标签 24px；不能再用极小文字挤出布局。身份色为商家蓝、服务商紫、平台绿、待识别琥珀。我方紫色加粗。原文只给身份标签上色，正文、姓名与时间保持中性色。

### 6.2 统一文字填写控件

单行、单号多行、资料编辑、搜索、时间共用一个组件及样式源：48px 基础高度、12px 圆角、14px 字号、22px 行高、上下 12px／左右 14px 内边距。

背景、边框、悬停、聚焦光晕、错误、只读与禁用状态共用定义。搜索／时间只增加图标空间和宽度变体；多行框无拉伸角标、按内容增高。不能靠每个弹窗单独追加覆盖样式。

### 6.3 动效

| 操作                       | 规则                                         |
| -------------------------- | -------------------------------------------- |
| 工作台／设置               | 选中玻璃背景上下滑动，内容轻微位移           |
| 商家／全部联系人、身份筛选 | 指示器滑动；保留筛选条和已有列表行           |
| 搜索、分页、筛选结果       | 局部更新与短高度过渡，不把整表透明度重置为零 |
| 勾选操作栏                 | 展开与收起，不因勾选重绘整表                 |
| 来源展开／收起             | 双向过渡，可中断反转                         |
| 按钮悬浮                   | 稳定位置，颜色和投影平滑变化；按压轻微缩放   |
| 太阳／月亮开关             | 滑块和图标过渡；同时更新整页主题             |

常用动效 160–340ms，主导航可到 360ms。支持“减少动态效果”，快速输入与连续切换取消旧动画。动画不能制造额外请求或延迟必要操作。

## 7. 实施验收

- 在 1180、1280、1440、1920px 桌面宽度核对；较矮窗口也能滚动编辑内容、始终触达保存。
- 来源折叠、导航、筛选、搜索、勾选栏快速重复操作不闪烁、不积压、不停在中间态。
- 对五类填写框比较实际样式和状态，不能只看截图上一个编辑器。
- 修改身份、填写、取消、保存、错误和重试均以真实状态响应，不只改按钮文案。
- 原型“演示整理”“微信未连接”只属于演示环境；正式版不能在真实失败后显示演示成功。
- 键盘焦点、Escape、表单标签、深浅色和减少动态效果一起验证。


## 2026-11-13：原文与共享控件反馈

- 沟通原文不展示system／revoke系统通知，避免未解码XML、模板和内部链接占满页面；底层原文、修订和来源保留。查询总数、搜索与分页按可展示聊天消息计算，不在前端分页后再丢行。
- 下拉菜单统一使用SelectField自定义列表，复用表单边框、字体和深浅色；选择色与勾选、键盘箭头／Home／End／输入定位、Enter确认、Escape／外部点击取消一致。长菜单可滚动并按可用空间上下展开，弹窗内不会被滚动区域裁切。退出动画期间旧菜单不再参与点击或辅助导航。
- 客户详情按内容测量高度，在上限内以280ms平滑伸缩；不缩放文字。页签切换、异步原文到达、查询变短和恢复列表均使用同一机制。菜单160ms展开／收起，原文搜索／来源筛选180ms保留旧行并弱化，收到最新结果后240ms淡入；加载更多保留既有节点。
- 所有CSS过渡遵循系统／应用减少动态效果设置；不靠空白占位等待查询、不重放过期搜索结果。模型未接入的阶段继续明确说明，不生成示例档案。
