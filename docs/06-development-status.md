# v0.1 开发与验证记录

本次交付是可运行的首版应用，不是全部目标设计完成。实际操作见 [运行指南](05-run-local.md)。

## 已实现

- uv 项目与依赖锁；本地私有数据目录；SQLite WAL、事务迁移 v1→v2 和一致性备份。
- 本机口令登录、Cookie、CSRF 与 Origin／Host 校验、页面转义、JSON 请求大小限制。
- 商家、服务商、备货项目、人工角色关联、会话白名单和独立 DeepSeek 外发授权。
- 标准消息导入、预览、原子校验、稳定 ID 去重、消息修订与未审核建议失效。
- wx-cli 只读 collector：源健康和账号核对、会话精确匹配、Text 正文、分页、固定窗口、近期回查及 gap 记录。
- DeepSeek 官方 endpoint 客户端、虚构样例连通检查、钥匙串／环境变量凭据、外发过滤与别名、JSON／证据校验、租约队列、有限重试及 token 预留。
- 待办建议审核／忽略、幂等建任务、责任方、状态版本控制、日期暂缓、人工联系记录。
- 价卡／海报条件手工录入、素材审核与撤回、具体报价快照、节点核验及项目完成关口。
- 本地工作台、消息与脱敏预览、草稿生成／复制；不自动发送。

## 已验证

- 21 项 pytest 测试通过：覆盖导入去重／修订、事务性失败、备份、真实源契约模拟、账号切换拒绝、全文缺失与 gap、DeepSeek 响应契约模拟、无效证据、政策撤销、预算、租约、建议接受、人工状态版本、会话安全、过期素材和备货核验。
- 一条端到端集成用例经过 collector → SQLite → DeepSeek 客户端 → 建议 → 真实应用 HTTP 审核接口 → 跟进任务与联系记录；两端外部服务均使用 MockTransport。
- 实际启动 Uvicorn，通过本地 HTTP 请求验证登录、HTML 页面、示例项目及 health；JavaScript 通过 node --check；Ruff 静态与格式检查通过。
- CLI init、demo、worker --once 和 backup 已执行；示例默认禁止外发，worker 正确保持政策阻塞，不会伪造成功。

测试运行在 Linux 云开发环境。受限沙箱中的 TestClient 线程事件循环不能完成唤醒，HTTP 集成测试改在允许本地网络／线程的执行环境运行；这不证明 Mac 上游可用。测试框架出现一条 httpx TestClient 兼容性弃用警告，不影响本次通过结果。

## 未验证与外部前提

- 没有真实 Mac 微信或 wx-cli 服务，未实测密钥取得、SIP 条件、客户端兼容、离线覆盖和原始消息身份。
- 没有配置 DeepSeek API key，未调用真实模型，模型别名／JSON 模式／usage 与费用仍待真实账户确认。
- 未测试实际商家资料或公司价卡；不会将其提交仓库。外发授权需要基于用户有权处理的真实数据范围。

## 下一轮优先级

1. 在 Mac 执行 source validate 和小范围同步，核对精确账号、全文、稳定 ID、方向与服务商角色。
2. 本地配置 API key，使用虚构 fixture 验证 DeepSeek，然后预览获准真实上下文并小批试运行。
3. 根据实际消息结构补充分片 local_id 兼容、周期历史回查、gap 恢复、长会话上下文与批次级归属。
4. 补充人工编辑、任务更新／语义合并、复杂责任人、定时提示、产品问题分类与更细字段级外发政策。
5. 评估 launchd 常驻和实际使用效果；暂不扩展云端部署。
