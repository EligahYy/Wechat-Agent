# 实施状态：v0.10.0 / 客户自动整理与跟进

更新：2026-11-09。完整资料分册底座已接入客户自动队列；默认工作台和后台使用新客户引擎。用户在“整理与进度”开启自动整理后运行，升级本身不会默默开启模型调用。

## 当前交付

1. **完整客户资料**：归集目标联系人已授权私信、出现过该联系人的群聊全部本地归档，从首次接触保留上下文、其他参与人回复、订单和媒体占位。先分册整理，再合并总结客户、批次和未完成义务，不按价值提前删消息。
2. **自动客户队列**：每分钟核对来源变化；优先近15天活跃联系人，但每位都从完整历史开始。历史联系人保留在队列中。优先续完已经开始的资料，避免只产生大量半成品。没有变化且已完成的联系人不重复分析。
3. **自动续跑**：每轮最多新增12次请求，达到上限后保存分册并自动继续；今日预算不足则等待北京时间次日，调高预算也能唤醒。用量与未确认预留保留，不清空账单记录。
4. **稳定来源快照**：每轮固定所读来源。分析期间新增消息放下一轮，不因活跃群不断追加而整轮失败；原文修订、人物／会话排除、授权变化或人工决定变化仍阻断旧结果写入。旧快照生成的档案明确标记新进展待整理。
5. **可控后台**：全局暂停在下一次请求及发布前生效，已发出的请求可能仍会完成计费，但不会因暂停继续发新请求。单联系人文件锁与队列文件锁防止跨进程重复运行；进程退出后的未完成项可恢复。
6. **失败处理**：网络、超时和限流按5／10／15分钟退避，连续三次后该联系人进入需要处理；认证、余额、接口配置错误暂停账号队列，处理后点击恢复。显式重试会允许重新生成失败响应，已验证分册仍复用。
7. **工作台收口**：登录默认进入客户工作台；设置和会话白名单入口保留。“整理与进度”提供开关、队列统计、分页、重试、分册进度和手动分析。今日待办分为今日到期、后续安排、等待回复和已完成；人工处理不会被后台覆盖。
8. **来源与疑点**：原文和分册可分页查看、按证据追溯；日期数字差异仅标记字段待核对，不删除独立成立的发货事实。归属不明的推断单独保留。已走货后的履约细节不产生新备货噪声，独立新一批仍可进入需求跟进。
9. **schema v12**：新增账号自动开关与客户队列表。升级前自动创建 `pre-v12-*.sqlite3`；已有聊天、分册、名单、用量、客户版本和人工处理记录保留。

## 使用方式

停止旧start／serve／worker后更新，使用 `wechat-agent start`（去掉此前的 `--pilot`）。登录默认工作台，在设置核对账号、key、文本分析授权和预算，在会话范围维护免跟进名单，然后在“整理与进度”开启自动整理。开关按工作账号保存，后续启动自动恢复该状态。首次历史整理可能较长，进度以每位客户分册计数为准。

`--pilot` 是纯手动模式，不运行队列；`--legacy` 显式运行旧模型后台，原工作台只通过 `/legacy` 访问。不要同时启动旧worker和新后台。新旧业务表独立，历史数据不会自动删除或混入新客户事实。

## 验证与边界

- 自动回归覆盖完整历史、分册复用、调用／预算续跑、新增消息与修订的不同处理、人工暂停与决定保护、失败退避、显式重试、优先级、锁、白名单、接口鉴权和数据库备份。浏览器使用虚构聊天和模拟模型验证主入口、自动开关、增量更新、原文溯源和待办交互。
- 用户已确认完整线索保留方向可用；测试不能替代真实DeepSeek业务准确率验收。模型仍可能漏提或归错批次，原文和分册可查，语义去重尚不完备。
- “全部”仅指本地已归档且已授权的相关会话，不保证源端未同步／隐藏／删除历史。图片仍是未识别占位，OCR、价卡理解、历史激活和话术推荐未实现。
- 群里其他人的消息是上下文，不自动成为当前客户事实。未明确商家、姓名无法定位、有未核实媒体／字段或新消息未处理时，不强推今日建议；关键确认按客户归纳。
- 分册与逐级摘要是有来源的压缩，不保证所有细节进入最终摘要。原始分册一直保留。合并不收敛、单条源数据过大等会停在需要处理状态，不能宣称完成。
- 当前不加入模型经验学习、全局经验文档或自动记忆总结；人工纠正只约束相应客户。
