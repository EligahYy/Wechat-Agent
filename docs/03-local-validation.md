# 本地实施与验收计划

状态：开发计划，所有命令均为拟实现接口，当前不可执行。目标是在本地形成可演示、可恢复的客户跟进闭环，再验证微信接入。

## 1. 开发顺序

### M0：导入与存储

实现项目骨架、锁文件、迁移、JSONL 校验、会话白名单、消息幂等入库和虚构样例。样例覆盖两个商家、私信、单商家群和混合商家群。

通过条件：重复导入不增重复消息；同样内容的不同消息仍分别保存；坏记录可定位；来源和覆盖范围可见；不需要微信或模型启动。

### M1：无模型业务闭环

实现商家关联、人工事实、任务状态机、规则建议、今日清单、联系记录、机会录入及规则草稿模板。

通过条件：可从样例完成“关联商家 → 审核建议 → 创建任务 → 复制草稿 → 人工确认已联系 → 安排下一次跟进”；用户编辑不会被重放覆盖。

### M2：本机模型分析

先检测可用内存与磁盘，再选择能在本机运行的模型及其固定版本；不在设计阶段承诺具体速度。保存模型标识、上下文限制和生成参数。实现结构化结果校验、任务更新建议和个性化草稿。

通过条件：模型停止时页面仍可用，任务不丢失；能区分分析失败与没有发现待办；不存在证据的输出被拒绝；人工评估通过后再启用日常分析。

### M3：真实 Mac 微信接入

确认工具版本、权限条件和目标会话范围；通过独立适配器转换为标准输入。真实 Mac 测试无法用 Linux 云环境代替。

通过条件：正文、消息身份和方向正确；私信／群均有代表性验证；断网、休眠、重启和分页后可恢复；不能补齐的历史明确标记；没有改写微信业务数据。遇系统保护变更要求时单独评估，不自动执行。

### M4：日常试运行

先选择约 10 家商家试运行一周，包含活跃、待成交、历史客户；该规模仅为建议。每日记录有效建议、误报、漏项及整理耗时，按实际结果调整规则。

## 2. 预期本地操作方式

以下命令是后续 CLI 的实现目标，仓库目前没有对应程序：

```bash
# 工作目录：Wechat-Agent 仓库根目录
uv sync --frozen
uv run wechat-agent init --timezone Asia/Shanghai
uv run wechat-agent import tests/fixtures/demo.jsonl --preview
# 在界面或 CLI 明确选定样例会话白名单后再正式导入
uv run wechat-agent import tests/fixtures/demo.jsonl

# 两个终端分别运行；初始使用规则模式，不依赖本机模型
uv run wechat-agent serve --host 127.0.0.1 --port 8765
uv run wechat-agent worker --engine rules
```

init 默认使用 macOS Application Support 下专用目录，配置非机密路径可覆盖；不写入微信数据目录。启动页面提示需要的本机会话登录方式。启动前检测端口冲突，不结束其他用户进程。

模型模式拟通过配置明确指定 localhost endpoint 和 model ID；配置中没有云端回退选项。健康检查同时展示 worker 心跳与分析引擎状态，仅有监听端口不视为就绪。

## 3. 必须验证的故障与边界

| 场景 | 预期结果 |
| --- | --- |
| 同文件导入两次 | 新增为零，任务与建议无重复 |
| 同文本／同秒不同 ID | 均保留，不误去重 |
| 缺 ID、无时区、非法方向 | 拒绝或隔离，并指出记录位置 |
| 同昵称不同联系人 | 不自动合并 |
| 混合商家群 | 模糊归属进入待确认，不自动给所有商家建任务 |
| 历史消息写“明天” | 依据原消息时间，不能按今天解释 |
| 历史已过期待办 | 默认待复核，不直接成为今日正式逾期 |
| 任务后续改期／取消 | 建议更新既有任务，用户确认后保留变更历史 |
| 用户修改后重新分析 | 不覆盖修改；冲突可见 |
| 点击复制但没发送 | 无已联系记录 |
| 联系后事项未解决 | 联系记录已更新，业务任务仍保持待办或等待客户 |
| 激活客户拒绝联系 | 候选被排除，不能靠模型绕过 |
| worker 在提交前后退出 | 租约可回收，重跑无重复正式任务 |
| 模型返回坏 JSON／假消息 ID | 校验失败，不污染客户事实 |
| 聊天里要求执行命令 | 作为文本，无工具执行 |
| 上游只有 snippet／分片失败 | 显示 partial／gap，不标成完整归档 |
| 分页期间补入历史消息 | 回查幂等合并，记录无法保证的覆盖范围 |
| 恢复备份 | 商家、消息、任务、人工修改及来源可用 |

## 4. 质量评估

先人工标注一组获准使用或虚构的样例，覆盖明确需求、闲聊、拒绝、引用、日期歧义、多个承诺和状态变更。记录评估集版本，禁止混入提示词样例再宣称泛化效果。

- 待办精确率：建议待办中真正需要处理的比例。
- 待办召回率：人工标注待办中被正确发现的比例。
- 来源可追溯：正式任务必须有可检查证据或标注为人工创建。
- 日期正确率：明确日期与歧义保留分别检查。
- 重复／错误归属：跨批次及跨商家单独统计。
- 草稿可用性：可直接采用、需小改、需重写、存在事实错误分别记录。

建议试运行门槛：证据校验与用户修改保护必须全部通过；业务建议精确率目标先设 90%、明确待办召回目标 80%，属于待实测目标而非已达到指标。样例数量和分布一起报告，不用小样本百分比代替效果说明。

## 5. 每个里程碑的交付证据

保存所执行命令、版本、通过／失败／未执行项和必要的脱敏错误日志。不保存真实聊天作为仓库测试样本。

M1 提供本地闭环演示；M2 提供模型评估记录；M3 提供设备版本与采集覆盖记录；M4 提供用户使用结果。只有 M3 通过才能声称支持实际个人微信持续采集。

## 6. 本地跑通后的决策

一周试运行后再讨论：是否需要常驻采集设备、是否需要远程访问、是否允许特定字段进入云端、是否使用外部模型、是否有多用户需求。任何一项均不作为当前本地版本的前置条件。
