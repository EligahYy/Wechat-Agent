# 同步整理与结果反馈重设计

日期：2026-11-16（北京时间）。状态：已按用户授权实施，云端回归与整体CR见[交付报告](../../verification/organize-outcomes-report.md)；Mac实测单列。用户要求重新给出整体整理方案，并让单客户整理记录显示客户名、准确简洁解释结果。

## 现状与问题

基线8a38550，Python503项、Rust来源服务36项通过。这些回归不等于Mac真实整理验收。

- `source/sync.py`在单客户路径检查来源中的全部群，任何群的成员未知／空列表都会增加`source_group_membership_unverified`，不区分与该客户的关联。
- `operations/worker.py`把任意`result.gaps`都视为来源失败并停止整理；因此已读完3/3已知会话，也可能无法生成资料。
- 会话已读完与全部群覆盖已证明是两个概念，当前只有一组缺口，界面把它们都称为“来源同步不完整”。
- `context/builder.py`和同步目标选择分别维护关联规则；历史本人发言所在群可能被选入，但整理上下文仍只含其本人消息，缺同群其他人语境，需统一。
- 记录只显示“单客户”，主要靠前端枚举错误码；错误阶段、受影响会话和后续动作未结构化保存。`updated_at`还被当作列表发生时间。
- 发布器已有证据、人工版本、角色和范围校验，必须保留。不能通过清空gaps或把所有失败降为警告恢复整理。

## 推荐决策

采用“已知关联范围完整可读即可整理”。用户已授权整体执行；对**已知会话读取失败**，本轮采取保守策略：受影响客户不发布，保留旧资料。全量任务中其他安全客户可独立继续。

已知范围包含：客户私聊（存在可读来源或已归档记录）、当前有效成员关联、已归档本人发言证明的会话。只在群目录出现、没有成员或发言证据的群，不作为该客户已知会话。历史发言证明历史关联，不等于当前仍在群。全量来源读取可维护归档，但模型只整理业务范围内已确认商家；身份未确认按既有业务意图发现流程处理，发现不会自动改身份；失败须记录原因，不静默吞掉，不宣称已整理商家档案。

关联规则实现一份`resolve_contact_conversations`供同步规划和整理快照使用；原文浏览消费其基础关联集合，继续保留“本人发言日历”和来源权限的现有过滤，不能把所有群消息或所有来源塞进客户页。

## 处理链路

1. 创建任务：即时返回；保存账号、客户ID、客户显示名快照、创建时间。客户改名后历史记录保留当时名称。旧记录用账号限定的当前名称回退，无法获取时显示“联系人（标识后6位）”，不伪造历史名。
2. 来源接入与刷新：沿用`.2`及账号、worker、代次校验；每次显式刷新。失败记录精确阶段与固定错误码。
3. 读取目标：建立已知会话集合；记录每会话成功、失败、未读完及原因。保留其他说话人的上下文。群覆盖未知不虚构新会话。
4. 每客户判定：相关已知会话均读完、无身份／归属／版本／归档阻断问题，才允许模型处理。无消息不能记为整理成功；未确认商家、人工移出业务范围分别说明未执行原因。
5. 整理：快照固定材料修订、有效人工资料、角色、范围、模型版本及本次覆盖结论。与上次有效输入相同才跳过模型；新增0条本身不能推出无需整理，首次生成或配置、人工版本变化仍可能需要模型。
6. 发布：原子重检所有版本及取消标记。范围未知允许有证据的正向更新，不允许借此否定其他需求或清空历史字段。未提及的旧字段在证据仍有效时保留；证据无法授权或修订已失效时不复制旧事实，也不默默删除，拒绝该次发布并保留旧head，展示具体原因。备货批次沿用身份及证据规则，人工值继续优先。
7. 汇总：消息读取、覆盖提示、模型处理、发布结果分别记录，再由唯一报告生成记录列表、客户提示条及详情。

## 问题分级及影响范围

| 情况 | 分类 | 处理 |
| --- | --- | --- |
| 来源不能枚举该客户全部群聊、历史完整性未证明 | warning／覆盖限制 | 已知范围读完可整理；不宣称全量历史完整 |
| 非目标联系人的名称或无关联群成员未知 | warning／非目标范围 | 不阻断该客户；无需在客户主提示堆叠无关详情 |
| 已知关联会话分页未读完、分片不可读、归属冲突、跳过异常原文 | blocker／会话 | 阻断依赖该会话的客户，其他客户可继续 |
| 账号不符、鉴权失败、worker变化、元数据代次变化、归档写入失败 | blocker／全任务 | 停止本次来源读取及后续新模型调用；已提交的安全归档保留 |
| 模型未配置／连接或预算未确认、超上下文预算、输出不合法 | blocker／模型阶段 | 明确已同步但未整理；旧档案保留 |
| 发布前人工资料、身份、业务范围或材料修订变化 | blocker／发布阶段 | 拒绝旧结果，不覆盖新资料 |
| 未知错误码、缺失范围的严重错误 | blocker／全任务（默认） | 不猜测放行；展示未识别原因及诊断码 |

错误归属必须由实际会话结果决定，不以字符串前缀猜影响范围。已知关联会话失败时不能只删掉该会话再宣布整理成功。本轮不实现任意部分会话的模型发布；以后另行设计。

## 结果与持久化契约

保留底层queued/running/stopped/succeeded/failed控制状态，新增版本化报告，避免UI自行从counts猜结果。

`OperationReport(version=1)`：`source_outcome=not_started|running|completed|partial|failed|stopped`、`analysis_outcome=not_started|running|updated|unchanged|partial|failed|not_applicable|stopped`、`scope_label`、`started_at`、`finished_at`、`contacts[]`、`issues[]`。`ContactOutcome`包括contact_id、名称快照、required/completed/failed会话ID、can_analyze、reason、analysis_outcome。`OperationIssue`包括code、stage（connection/metadata/messages/context/model/publication）、severity（warning/blocker）、scope（operation/contact/conversation）、contact_id/conversation_id可空、suggested_action（retry_sync/open_model_settings/review_contact/none）。只存固定码和本地对象标识；不上存请求体、原文、密钥或供应商原始错误。

模型发布成功与覆盖未证明可同时成立；例如source_outcome=completed、analysis_outcome=updated、issues含覆盖warning。全量一部分客户阻断、一部分完成时报告partial；底层任务state保持failed以兼容控制，不伪造全成功。已知范围与历史完整性始终分开，history_complete仍为false。

记录旧数据不重算成成功，不自动重跑付费模型。report为空时提供旧记录兼容提示，已有客户ID可回退展示名称；无法知道的错误显示“此旧记录未保存具体原因”。

报告稳定语义写入快照覆盖字段；重复任务ID、发生时间、展示名称不参与“输入是否相同”判断。范围集合及警告变化参与判断。任务与快照均须账号限定。

## 记录交互

列表首行：`兴🌟 · 整理完成`；次行：`今天20:36 · 3个已知会话 · 无新增消息`。有范围警告附轻量“有范围提示”，不使用失败红色。时间以创建时间排序，进行中可显示持续状态；完成时间放详情。

展开结构固定为：

```text
兴🌟 · 整理完成
消息同步   已完成 · 3/3个已知会话 · 新增0条
资料整理   已更新（或：输入未变化，无需更新）
范围提示   无法确认是否还有其他关联群，已按已知范围整理。
[诊断详情]
```

失败显示：`兴🌟 · 未能整理` → `消息同步：2/3会话已完成` → `原因：某关联群读取超时` → `影响：本次未更新资料，已有资料保留` → `[重新同步]`。只在source_outcome失败时说来源失败；模型失败说“消息已同步，模型整理未完成”；主动停止不能写失败。空材料说“暂无可整理消息”，不显示“输入未变化”。

诊断详情才展示技术码、会话ID、修订和不变消息数。列表及详情主路径不展示原始英文错误串。不新增自动重试循环；重新同步复用现有创建任务API并生成新幂等键，不增加调度器。

## 验收边界

必须通过：未知无关群+3/3已知会话仍可首次整理；已知会话缺页不发布；全量中安全客户继续；新增0但无档案仍调用模型；输入相同跳过；覆盖受限不抹除旧资料；人工并发拒绝覆盖；重名、改名、已删除联系人和旧任务均可读；点击不同记录展示对应结果；警告、失败、停止均有准确文案和动作。

不扩大本轮为M3分段／附件下载解析、M4调度、联系人自动合并或重新定义业务范围。本次不需要再次修改wx-cli协议，除非实施时出现新的独立证据。云端通过和Mac真实恢复分别记录。
