# 联系人原文统一查询与性能改造

2026-11-15。用户要求审查影响并一起修复读取、切换及每次定位刷新的问题。本方案补充日历双栏设计；最新规则覆盖原设计中的灰点和纯群上下文日期。

## 审查结论

- `messages/queries.py` 的逐会话相关 EXISTS 在日历、数量、定位和分页中反复执行。150000条合成消息、802个会话、原有索引下，日历12749ms、一次本人定位30556ms；2个会话时分别约171—186ms、150—161ms。不是Mac实测。
- `messages/calendar.py` 每月还查全历史MIN/MAX、全群消息月份统计；`julianday`排序与日期过滤不匹配现有TEXT时间索引。
- `api/messages.py` 每页逐条查附件，缺少按消息的附件索引；归档MAX(rowid)缺少专用账号索引。
- `MessageTimeline.tsx` 每次上下定位都请求完整窗口、计数变成省略号，且用定位版本作列表key导致列表重新挂载和动画。
- `MessageBrowser.tsx` 先等日历再读取正文，无月份缓存，月份、来源及原文刷新之间职责混杂。

## 方向与边界

采用现有消息事实表加表达式索引，统一浏览范围和有界读取。不复制聊天，不先建需要回填和修订撤销的按人消息副本。持久化逐日汇总留待有证据需要时再做。

“本人”是当前联系人，判断为同账号下`sender_id=contact_id`，不按姓名、群成员、提及或转发内容猜测；不做同名ID合并。我方包含账号ID及全部is_self身份。

群来源须有本人实际的非system/revoke发言；日历蓝点只统计本人发言，不显示灰点。选中一天后，群上下文只来自本人当天发言的群，保留这些群当天其他人的消息。先确定会话集合，再用关键词筛正文，不能因本人未命中关键词丢掉其他人的匹配消息。所有来源保持时间及message_id稳定排序。

已验证的双人私聊是独立依据：仅我方发言也可访问，无第三人或归属不明的消息污染；目录中的空私聊不构成记录。私聊上下文不会被记成本人发言。默认当月最新本人发言日期，月内无发言则通过索引找最近本人发言；完全无本人发言才回退最近有效私聊。日历保留过去日期的选择能力，零发言日无蓝点，可显示有效私聊或空状态。“回到最新”同样按当前来源定位，保留搜索词；不触发同步或模型。

## 后端与索引

`messages/queries.py`集中校验联系人、列出有发言来源／有效私聊、解析当天会话集合。来源由发送人索引直接列出，仅对候选私聊校验双方身份，不遍历账号全部群；每个请求只解析一次，后续查询使用同一集合。

新schema11迁移仅增加查询索引：可见消息的账号／作者／标准时间／ID索引、账号／会话／标准时间／ID索引，附件(account_id,message_id,attachment_id)，message_revisions(account_id)。保留现有原始sent_at和修订记录，标准时间表达式采用与现有查询一致的julianday，保留北京时间日界与时间精度，禁止直接按混合offset的ISO字符串比较。

日历只统计本人当月发言；首末日期使用作者索引取首末一条，不再扫描群全部历史。每页最多50条正文，附件一次批取。定位序号与相邻本人ID共用日内范围，并返回当前窗口本人发言的位置元数据，支持浏览器准确本地定位。关键词、来源、日期和所有排序边界一致。

游标仍绑定账号／联系人／来源／关键词／日期／页大小／方向及归档版本。来源、日期范围规则改变后旧游标返回409，不能静默继续。账号授权和隔离身份校验在每次后端请求执行。

## 前端

左日历、右正文和窗口尺寸不变。当前月先读；切月只读取该月元数据，不替换正在阅读的日期。月份及最近日期窗口使用组件内有界缓存（最多6个月、6个窗口，30秒有效），按账号／联系人／来源／日期／关键词／revision隔离；revision变化清空，过期重取，关闭联系人后释放。新联系人不会继承旧联系人结果。

本人定位目标已在窗口内时直接更新当前位置、计数和滚动，不发请求、不重新挂载列表、不重复入场动画。目标不在窗口时只请求其附近上下文；保留原消息和计数，防止重复点击并显示轻量忙状态。失败保留当前位置，可直接再点重试。滚动补页合并定位元数据、去重消息，保留可见锚点。

保留请求取消及响应代次检查；新日期／来源／关键词错误时，不把旧数据显示到新条件下。资料页签来回切换保留阅读位置。缓存只用于展示，不承担权限、模型事实或业务范围判断。

## 功能影响

| 功能 | 改造范围／兼容要求 |
| --- | --- |
| 日历／来源／定位／搜索／正文分页 | 共用浏览查询；群上下文按本人当天发言收敛；只蓝点；搜索及稳定分页保留 |
| 私聊／非商家查看 | 保留已验证私聊及无本人发言的私聊落点；身份不限制为商家 |
| 同步／导入／历史修订 | 索引自动跟随同事务写入；改作者、时间、类型立即撤销旧蓝点；导入幂等和同步cursor不变 |
| 姓名／身份／附件 | 保留姓名证据解析、隔离、展示角色、安全下载；revision或30秒有效期防止展示缓存永久陈旧 |
| 模型profile快照 | builder独立按既有完整归档范围、cutoff和revision冻结；本轮不以日内浏览范围替换；冻结来源读取不受日历限制 |
| 群需求发现 | 保留90天本人发言、同群前后各2条及向前引用链，继续验证引用作者 |
| 业务联系人 | 人工排除优先、90天直接互动／需求发现保持；activity独立全账号推导开销记录为后续事项 |
| wx-cli | 读取本地归档的瓶颈在本项目，本轮不改源端协议／版本 |

模型snapshot使用群成员范围时可能比浏览来源广，是当前既有契约；后续M2任务4／7应验证不把群中其他人需求归给目标，不能靠浏览器过滤掩盖。业务activity即使命中缓存仍会先读全账号生成hash，属于另一条性能路径；本轮不把它与浏览查询强行合并。

## 验收

行为覆盖两群跨日、目录成员未发言、本人未命中但他人命中关键词、私聊仅我方、多self身份、污染私聊、作者／日期／类型修订、跨时区午夜／同时间ID、导入幂等与cursor、跨账号及旧游标、特殊消息摘要及附件批取、缓存命中／失效／竞态、上下定位DOM保持。

性能用与基线一致的150000条／802会话合成库测日历、当天首屏、本人定位；另外用SQLite进度回调设工作量上限，阻止逐会话全历史扫描回归。目标相同环境单项低于500ms，并报告具体结果，不作为Mac响应承诺。已加载上下定位要求零HTTP请求，切月不拉正文。最后运行完整Python、前端单元、E2E和Node24.14.1构建，一次独立只读审查后提交推送。
