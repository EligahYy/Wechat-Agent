# 客户资料整理链路审查与改造计划

## 本次现场

整理记录显示，3 个已知会话已同步，1,019 条原文中有 135 条高价值原文。分段从 9 个增至 13 个，7 个分段通过校验，覆盖 71 条原文。提取阶段耗时 377.2 秒，共发出 20 次模型请求，最后记录为模型输出格式不合约定。记录没有保留供应商原始响应，仅凭截图无法确定具体的 JSON 或字段错误，也无法确定 20 次请求中各类重试的占比。

## 当前实现

| 环节 | 当前行为和问题 |
| --- | --- |
| 原文同步与归档 | worker 先同步并记录来源覆盖，再由 runner 固定客户快照。确认会话都已读取只说明已知范围读完，不能证明所有关联群都已覆盖。 |
| 原文筛选与分段 | 高价值路径以字段规则筛选原文，按输入容量和原文大小装箱。此前大量普通对话也标记为需复核。本轮收敛人工队列，只有可归属且涉及业务字段或明确变更的原文进入队列。 |
| 调用与校验 | 网关有请求期限和轮次预算，工作流还会做格式、引用纠正，以及针对超时或截断的拆分。这些路径共用一次任务的请求预算，存在已推进多个分段、整体仍以单个错误结束的情况。 |
| 归并与发布 | 系统已能本地归并部分字段，其他场景可能再次调用模型。提取阶段仍有失败时，当前流程停在检查点，归并和发布不运行。因此本次的 71 条已校验原文不会出现在档案里。 |
| 继续整理 | 本轮将可恢复的格式和引用失败、临时供应商错误及单段调用额度接入同一恢复规则。继续整理优先复用满足版本、身份和来源约束的归档及检查点，仍遵守供应商冷却时间。 |

## 下一步实施顺序

1. **统一可恢复任务。** 以冻结快照为输入，以原文稳定编号和修订为证据。每个分段持久化覆盖范围、候选事实、尝试次数、耗时与当前状态。明确区分模型输出无效、供应商暂不可用和本次额度耗尽。同一轮只有一个地方决定重试、拆分或暂停，网关只负责发出一次请求并分类结果。继续任务从未完成的叶子分段接着处理，旧检查点只有通过版本和权限复查才可复用。
2. **缩短模型链路。** 先用包含证据引用的简短结构提取事实，按实际输入和预期事实数分段。允许本地处理等价的格式差异，校验每条事实的出处与修订。优先本地去重、归并一致事实和标出冲突。仅将确实需要语义判断的冲突和批次关系交给模型，按字段分别处理。记录每个分段首次成功率及校验、重试、归并分别消耗的调用。
3. **分开校验进度、部分更新与完成。** 已校验的候选可先预览。后续实现部分发布时，按字段判断证据是否充分以及缺口是否影响该字段。已有确认值、人工覆盖、来源冲突和未完成批次受到保护，任何写入都重新检查身份、快照、修订和并发版本。明确显示哪些资料已更新、哪些仍待核对或未完成，只有需要处理的范围达到验收条件才标记完成。
4. **复核落到档案字段。** 优先列出影响字段取值的冲突或缺少的关键证据，附原文和来源跳转。来源范围、分级和分段信息保留在诊断。按字段聚合的复核取代逐条确认中价值消息。

## 验收顺序

| 回放场景 | 判定条件 |
| --- | --- |
| 10–40 条高价值且一次响应能放下、无事实冲突 | 正常响应只请求一次，校验与发布均执行；记录分段耗时和首次成功率。 |
| 1,019 条原文，135 条高价值，后段格式异常 | 已校验分段可见且持久化。继续时不重复同步已冻结来源，也不重发已校验且仍有效的分段。重复失败应表现为明确的分段状态。 |
| 超时、限流、截断、错误结构、跨段与跨客户引用 | 响应异常有不同原因与对应动作。续跑遵守冷却，同一次尝试有明确调用和时间边界。跨客户证据禁止发布。 |
| 来源缺失、归属冲突、人工编辑、原文修订、应用重启 | 缺口显示在受影响的字段或来源；快照权限或者引用变化后重新校验；已确认的字段和人工覆盖受到保护。 |
| 干净样本、混合群聊、否定或取消、附件待解析 | 对照人工标注统计字段召回、冲突识别、复核条数、调用次数和耗时。保留高价值原文的筛选收益，同时核对遗漏。 |

本轮交付弹窗滚动、整理状态区、复核入口及继续整理。以上四项为后续改造计划，真实微信来源与供应商端到端耗时需要在 Mac 样本上测量。
