# M3 整理链路审查修复与验收

2026-11-18，workflow-v4 落地。schema 19 增加单元重试窗口和快照材料指纹，原有档案与模型调用审计随升级保留。

| 修复 | 验证 |
| --- | --- |
| 合并完整性 | 从 worker 回放两个不同报价，模型漏掉一项后改用已验证候选组装。发布版本保留两个报价及原文引用。合并期间暂停后跳过已判定缺项的父请求。 |
| 沟通字段 | 单候选保留摘要状态、标签与时间。多个候选按可验证的业务时间处理，同一时刻冲突标为待核对。 |
| 拆分恢复 | 九个需要细分的窗口中，第 9 个由后继任务继续，前八个窗口复用已验证子段，主材料覆盖检查通过。 |
| 临时失败恢复 | 回放 429、503、提前重试、达到冷却后的重试及长 Retry-After。历史耗尽项只有能确认六次均为临时服务错误时才恢复。 |
| 快照复用 | 重复整理通过材料指纹命中已发布快照，跳过正文查询和新快照写入。模型调用数保持不变。材料修订使指纹失效。 |

本地 SQLite 使用合成数据。在已有四条消息的测试库分别追加 1、1000、10000 条消息，复用已发布快照分别约耗时 0.3、3.4、47.8 毫秒。每次复用均只按两个会话查询附件，无正文查询和新增快照。该测量只覆盖本地准备步骤。

不同事件时间、批次归属或阶段信息无法同时装入现有单值结构时，保留旧档案和已验证分段，整理记录提示归纳未完成。旧版提取检查点仅在请求内容和材料完全匹配时复用。合并缓存和未经新策略验证的已发布档案使用新策略重新核对。
