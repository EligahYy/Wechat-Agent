# 整理记录详情交互排查与回归

日期：2026-11-15（北京时间）。维护范围为整理记录交互及模型配置说明，不推进M2任务6或7。

## 根因与修复

原实现把选中详情固定渲染在历史列表前面。用户滚动后点击较早记录，GET成功且选中状态变化，但详情在视野外。现改为单项原位展开／收起，提供aria-expanded和详情区域关联；换选、关闭或重开时取消旧详情请求，旧响应不能覆盖新选择。失败在当前项内重试。

独立只读审查发现客户快捷入口可能继承旧列表滚动位置，已增加用例实际复现，再修为打开后一次性定位到目标详情。手动列表换选不触发该定位。

## 整理链路与模型参数边界

`api/settings.py`仍报告organize=False；`operations/worker.py`来源同步完成后，对需分析的商家写入capability_not_ready，而非调用真实模型。记录详情不可见是前端交互问题，生产整理尚未接通是另一个已知阶段边界。

截图中的HTTP200不能证明来源同步或分析成功。“来源同步不完整”的具体缺口须看该记录的source items，不能仅凭访问日志推断是网络、群覆盖还是解析问题。

DeepSeek官方文档访问被云端网络代理拒绝，未核实用户提到的v4.1-flash精确API模型标识、窗口和专用开关；未编造模型预设。Mac指南提供完整chat-completions地址、JSON对象模式、以服务支持额度为前提的32768／8192起始预算。未保存真实密钥、未调用供应商、未宣称模型能力通过。
