# 整理链路改造与架构审查

2026-11-16（北京时间）。本轮针对“3/3会话已读完仍全部阻止整理”和记录无法解释结果。Mac真实模型质量及本次恢复待实机验证。

## 架构与职责

```mermaid
flowchart LR
 A[创建任务与名称快照] --> B[来源接入及显式刷新]
 B --> C[会话读取与归档]
 C --> D[按客户覆盖评估]
 D -->|允许| E[固定材料与覆盖快照]
 D -->|阻断| H[持久化客户结果]
 E --> F[输入比较与模型工作流]
 F --> G[证据与版本校验后发布]
 G --> H
 H --> I[统一记录和客户提示]
```

- `contacts/conversations.py`统一私聊、成员和历史本人发言的关联集合；`context/builder.py`消费同一集合保留同群其他人的语境。日历保留本人发言过滤，本轮未扩大为账号所有群。
- `source/sync.py`负责刷新、逐页读取、租约／游标、事务和逐会话错误事实。新增conversation_gaps避免把不同群错误混为一谈。全局严重错误停止后续会话读取。
- `source/coverage.py`负责允许／阻断及影响范围。覆盖未验证是warning；已知会话未完成、原文归属异常及未解决隔离记录阻断相关客户。未知严重错误保守阻断。
- `operations/worker.py`编排任务；`analysis/runner.py`只整理获准客户，业务意图发现也受准入控制，失败记classification_failed。全量任务保留安全客户的完成结果。
- `context/contracts.py`冻结规范化覆盖集合、警告和策略版本；重复任务ID和时间不参与输入是否变化。M2历史超预算仍拒绝，不截断后伪装完整。
- `profiles/publisher.py`继续原子检查角色、业务范围、人工版本、材料修订和取消。新的生产覆盖快照启用保守旧字段保留；备货批次字段省略同样保留有效事实，无法授权时拒绝整次事务。旧快照兼容原策略。
- `operations/reports.py`保存版本化结果和按客户原因；底层RunState用于队列控制，报告outcome用于解释实际结果，两者职责不同。全量部分成功的控制状态保持failed，报告明确partial，不删除成功资料。
- `operations/service.py`和API用账号限定JOIN批量读取任务、名称与报告；20条记录不再逐条查联系人和报告。名称快照不随改名变化；旧记录只读回退当前名称，不伪造历史名称。
- `frontend/src/app/operationOutcome.ts`集中标题、原因和动作；`OperationHistory.tsx`负责稳定时间排序和单条展开；`OperationDetails.tsx`主路径显示阶段、人类可读原因及后续动作，技术信息折叠。

## 行为及兼容边界

1. 无关群成员未知不阻断已知范围整理；未证明全部群覆盖仍明确提示，不宣称全历史完整。
2. 已知会话失败时该客户不发布。全量其他客户可继续，重试时输入不变的已完成客户跳过模型。
3. 新增0条不能推出无需整理：首次档案、人工／模型版本变化按固定输入重新判断。
4. 同步失败、业务意图发现失败、模型失败、发布冲突和用户停止分别记录，模型配置问题不倒写成来源失败。
5. 读取页数全部完成但存在未解决归属异常时，显示“会话已读取，仍有消息异常”，不以3/3自动宣布可整理。
6. 旧任务不重算成成功、不自动重跑。schema14→15只新增可空名称和报告表，旧模型快照coverage默认None可继续授权读取。
7. 群成员已知更新会移除陈旧的source_membership；本人历史发言仍能证明历史关联，不伪称当前仍在群。

## 测试方法

`tests/fixtures/organize-scenarios.json`含45个合成场景；`tests/organize_scenarios.py`严格拒绝未知控制字段，以真实SQLite、同步器、worker、WorkflowV1、快照和发布器执行。模型Gateway及来源I/O采用合成回放，不连接DeepSeek或真实微信。每例检查来源／整理结果、模型请求数、发布与原因；相应场景增加旧head、人工值、来源隔离、名称、跨客户、上下文和批量隔离断言。

来源错误场景部分通过固定SourceError注入；真实HTTP的v2刷新→元数据→分页契约另由`test_v2_http_refresh_metadata_and_page_contract`回放。真实模型预算、重试和证据边界继续由既有网关测试负责；合成Gateway不能证明模型语义质量。

另外覆盖：全量部分成功重试不重复付费、退出成员清理、历史隔离消息仍阻断、批次旧证据失效回滚、历史名称不回写、20条列表无N+1、警告／模型失败／部分客户／旧记录以及部分字段待核对五条新浏览器路径。旧的浏览器mock显式report=null，避免把新报告和伪造旧控制状态混在一起；真实任务断言按新语义更新。

## 审查发现及处理

实施中风险检查复现了备货批次字段清空，并发现成员陈旧、业务意图发现门禁、报告阶段／姓名及列表N+1等问题；均进入修复与回归。最终整体CR发现三项Important：部分合法输出被误报全部完成、运行配置初始化失败被误报无材料、全量任务遗漏覆盖未验证警告。均用失败测试复现后修复；输入不变跳过时也保留先前字段待核对提示。Minor中的仅刷新元数据统计被新报告遮盖、故障回放未模拟读取中途变化已一并修复。最终不再重复派审查，修复后执行完整回归。

验证结果：Python **589 passed**（含45个数据驱动完整链路场景）；Vitest **36 passed**；Playwright **71 passed**；Node24.14.1生产构建成功；wheel后端／迁移资源逐字节核验及独立静态服务烟测通过。中途读取身份／代次变化、SQLite真实写入失败且无半条归档、旧任务3/3仍失败、部分批量重试只调用恢复客户等均有回归。

Ruling：空模型候选仍以empty_result安全拒绝并保留旧head，不为没有正向证据的输出造新版本。旧无coverage快照继续旧发布规则；新的保守策略只用于本轮生产覆盖快照，避免更改历史证据读取语义。

Ruling：前端继续由仓库frontend/dist独立构建与API静态服务交付，沿用现有打包方式；Python wheel校验后端及迁移字节，前端另做构建和静态服务验证，不虚称前端资源已经打入wheel。

Ruling：关联集合服务于同步与分析；浏览器继续使用有索引的本人作者查询，按本人实际发言缩小可见群和日期，保留上下文，不强行替换成更宽集合而退化查询性能。SyncResult保留错误事实与conversation_gaps，由Assessment统一生成结构化issues，避免两份解释状态。Task1—4及后端测试原子提交，前端与文档分别提交。

业务意图发现仅产生业务信号，不自动修改身份；人工排除和确认身份继续优先。分页读取仍是有界读取与修订检查，不是全历史原子快照或增量订阅。

## 安装与实机验证

已使用`.2`来源的机器无需再次重装来源或Rust。按[Mac更新步骤](../MAC_SETUP.md)更新代码、构建前端并重启8766，启动自动迁移schema15。保留原归档和Keychain，不清空数据库。

依次验证：无旧档案且无新增消息的商家可首次整理；已知范围完整但其他群未知能更新并显示提示；真实读取缺口时明确客户、会话原因和旧资料保留；模型未配置／失败时来源仍为已完成；记录切换、客户改名和重新同步动作正确。首次按新覆盖策略整理可能重新调用一次模型，之后相同有效输入应跳过。

仍未交付：任意部分会话材料下的发布、长历史分段、附件解析、每日调度、无人值守和真实资料质量验收，分别留给M3／M4／M5；本轮不借“部分成功”绕过这些边界。
