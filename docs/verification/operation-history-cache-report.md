# 整理记录缓存与卡片反馈修复

2026-11-16（北京时间）。范围：新记录切换后消失、详情布局与列表不一致、结果卡片颜色。

## 根因

任务已持久化；刷新后主入口可读取。前端useOperations仅在启动／打开历史时加载列表，提交和轮询只更新job。客户快捷入口把不在缓存中的当前详情临时渲染在列表外；换选旧记录后临时节点消失，所以新记录无法再次选择。这不是来源同步或模型未执行导致的记录丢失。

## 实现

- 提交／轮询的job、详情读取及客户快捷入口均按任务ID归并到同一历史缓存，按创建时间排序；旧摘要缺少创建时间时保持服务端顺序，避免按进度时间重排。
- 列表请求与本地已观察记录合并；旧updated_at不能把终态倒退为处理中，列表摘要不能清空已读items。
- 账号切换清空缓存，忽略旧账号迟到的列表响应；不持久化跨账号前端缓存。
- 取消列表外临时详情；快捷入口、主入口均使用列表记录头＋原位展开／收起。
- 新报告详情采用与旧记录一致的标题、统计标签、阶段信息和提示卡片；诊断仍折叠，去掉重复客户名。
- 卡片底色和边框显示结果：失败红、成功绿、部分完成／字段待核对橙、进行中蓝、停止灰。客户名和结果文字保留原样；只有群覆盖未验证提示的成功任务仍为绿色。部分完成虽在队列控制中为failed，卡片按实际partial显示橙色。

## 预算说明

处理预算来自模型配置中的上下文上限及最大输出，网关预留10%安全余量。现实现用UTF-8字节保守估算（含消息、结构及输出），不是准确token计量。模型容量本身有上限，未增加虚假的“不设上限”按钮；超窗自动分段仍属M3，不能以移除校验或截断历史替代。修改容量必须依据供应商文档，并重新保存与核对文本预算。

## 验证

先写失败用例，复现新任务不入历史缓存、轮询终态未更新历史；浏览器复现客户快捷入口只有旧记录列表。修复后增加旧列表迟到、详情归并和账号切换回归。

最终验证：前端单元42项通过，Node24.14.1生产构建通过，应用实际服务当前HTML／JS／CSS通过。完整浏览器回归71项通过，1项新增用例因嵌套定位器从错误根节点查找失败；仅修正测试定位器后，全部记录专项10项重跑通过。其余62项在完整回归中通过，全部72项均有最终生产代码的通过证据；不把上述首次全量记录为72/72单次成功。已检查展开后的截图，标题、统计、提示及红色卡片布局正常。

缓存、终态同步先红后绿；旧摘要排序兼容由完整浏览器回归暴露并修复。绿色卡片底色和红色卡片底色有真实浏览器计算样式断言，颜色状态覆盖失败、成功、部分完成、进行中和停止。

云端使用合成来源和模型；本次没有调用真实模型或修改用户配置。后端与schema不变。

## 更新与实机核对

Mac只需pull main、构建frontend并重启8766；无需迁移来源服务或清空归档。验证新建一项整理任务后直接从主入口打开记录、从客户快捷入口打开后切换旧记录再切回，以及刷新后保留同一条记录。分别核对成功绿卡、失败红卡及部分完成橙卡。此次界面修复不解除超窗门禁，也不会自动改变模型配置或重跑失败任务。
