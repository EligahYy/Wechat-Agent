## 自动化证据

M0交付时云端Python全套99项测试通过，用户Mac复验也是99项通过。后续M1增量见[M1报告](m1-report.md)。覆盖：

- 未配置时pending、默认离线、Mac／Linux状态区分、已有Python路径和空格路径。
- 同名不同ID、账号隔离、群不是人物、完整正文／引用、稳定消息ID、分页／跳行／分片缺口、账号或worker变化。
- 固定loopback、只读GET、不走环境代理、不跟随重定向、鉴权和服务错误不伪装为无新增。
- 明确配置的最小模型请求、401／403／404／429／服务错误、模型别名、错误JSON、截断、用量未知、密钥与推理内容不导出。
- 质量不从文件名猜测、空文件／目录／权限错误、SHA-256、原文件不修改、不执行文件、反馈报告不含原文／姓名／路径／凭据，报告不能覆盖输入文件或配置。
- 缺发送人仍报pending，计数区分采样／有效／未通过；异常类型跨分页保留至shareable报告，非法元数据不回显。

TDD记录：来源先22个缺失功能失败，模型先24个失败，媒体先10个失败；自审问题分别补失败测试后修复。后加的URL回归直接通过，未冒充新复现缺陷。没有在云端调用用户真实微信或付费模型。

实机缺发送人反馈后，新增9项诊断回归先失败再通过；当时未假定异常类型。用户随后回传确认2条群系统事件；按明确类型允许空人物归属，普通消息约束不放宽，云端新增11项事件回归（9项先失败、2项既有行为已通过）。详见[Mac验证记录](mac-validation.md)。

## 本轮实现取舍

| 决定                           | 原因与边界                                                               |
| ------------------------------ | ------------------------------------------------------------------------ |
| 复用第三方wx-cli HTTP服务      | 用户已有同版本服务；独立协议层隔离，不恢复旧业务，上游变化需复核         |
| health先验账号，再有限采样     | 启动目录选择值不等于canonical wxid；不匹配不读消息，连接成功不证明全历史 |
| M0输出计数，不自动保存聊天样本 | 减少诊断暴露；完整原文归档和来源定位由M1交付，当前没有业务档案           |
| 模型探测不猜Pro ID、不自动重试 | 真实ID由配置确认，短请求不证明大窗口、视觉或档案准确性                   |
| 媒体只确认可读和指纹           | 文件存在不等于原件或读懂内容，解析在M3                                   |
| 当前代理自审                   | 用户选择串行、无子代理，未宣称独立审查或真实模型验收                     |
