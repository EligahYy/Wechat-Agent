# 联系人原文查询审查与性能验收

2026-11-15。原基线0ef4adc；[影响与设计](../superpowers/specs/2026-11-15-message-query-optimization-design.md)、[执行计划](../superpowers/plans/2026-11-15-message-query-optimization.md)。

## 问题与改造

1. 原来源规则逐个会话相关查询，再由每条计数／分页／定位查询重复执行。现在直接从当前联系人发送者索引列群来源，仅对其候选私聊核实两方关系；日内群集合由当天本人发言一次解析，其余查询复用集合。
2. 原日历计算所有群上下文首末时间、全部日期和本人日期。现在只统计本人当月日期，首末日期按作者时间索引取一条；仅我方有效私聊仍有最新记录落点，不伪造蓝点。
3. 新schema11增加时区一致的表达式时间索引、附件按消息索引和revision按账号索引；不改源时间文本、聊天修订／同步cursor及模型取材。附件一次批取。
4. 当前窗口返回准确的本人位置／邻居元数据。已加载定位本地完成，无HTTP、消息DOM保持、计数不闪省略号；跨窗口请求保留当前消息及计数，失败可直接再点重试。
5. 月份／窗口缓存各最多6项、30秒有效；按账号／联系人／筛选／日期／revision区分。请求取消和代次检查保留。日历只蓝点，日内其他说话人仍保留。

## 现有功能影响

- 有意变化：纯群上下文日期无点；群上下文只来自本人当天发言的群；默认落点优先本人最新发言，完全无本人发言时使用已验证私聊。
- 兼容：过去空日仍可选择；仅我方私聊可读；多self身份、非商家、关键词仅命中他人消息、混合offset时间、同时间ID排序保留。
- 同步和导入共享事实表及索引，修订作者／日期／类型立即反映到日期和范围；没有新增易残留的按人消息副本。导入仍幂等、不推进真实来源cursor。
- profile快照、discovery90天／邻域／引用、业务范围人工排除逻辑未改。它们可共用时间／身份事实，但不能直接套日内UI范围。
- 姓名、隔离身份、角色、特殊消息摘要和安全附件逻辑保持。读缓存不作为模型来源或后端授权。

## 可重复合成性能

云端Python3.12／SQLite，150000条合成消息，2025-11-15起每3.5分钟一条，约1/41本人发言，其余另一说话人；802个会话（2个有效，800个无关目录会话），不含真实客户信息。读时不访问wx-cli或模型。

| 操作 | 原有索引／代码 | 改造后3次（ms） |
| --- | --- | --- |
| 当月日历 | 12749ms | 2.80 / 1.40 / 1.28 |
| 当天最新窗口 | 未在802会话原版单列 | 2.72 / 2.80 / 2.06 |
| 本人定位窗口 | 30556ms | 2.35 / 2.27 / 2.59 |

数据和输出位于忽略目录`.local/evidence/message-performance/`，不将合成库或运行日志写入仓库。以上是查询函数耗时，不是HTTP端到端或Mac承诺；原测试还包含2会话的基线，不能混作同一规模比较。

回归`test_unrelated_conversation_count_does_not_multiply_message_scans`给SQLite指令量设置上限，在增加无关会话及旧消息后仍能查询月历和当天窗口，避免仅用易波动的毫秒阈值。

- Python全量：417 passed。

- 完整浏览器49 passed；独立审查后补2条“回到最新”缓存边界均通过。Node24.14.1最终构建通过。
- 改造前红灯：旧代码无法通过纯上下文日期撤销、修订、有效私聊仅蓝点、查询工作量、位置元数据、窗口内零HTTP和月份缓存用例；改造后相关用例已转绿。

## 后续边界

业务activity当前即使命中派生缓存也需全账号读取并生成hash；profile上下文按成员取材比原文UI范围广。这两项应分别优化／验证，不能把原文页的当日规则作为模型和业务范围事实。真实Mac耗时及库规模仍需用户更新后观察。本轮不依赖wx-cli、Rust、模型或新依赖安装。

## 独立最终审查

只读审查确认仅我方私聊、修订撤销、关键词独立于会话依据、授权／游标、窗口位置合并和账号缓存边界；发现“回到最新”命中中间窗口／旧高亮的缓存问题。两个浏览器用例分别观察到旧落点／旧计数失败后，修正latest操作识别及末尾窗口高亮，两例已转绿；最终完整回归417／31／49全部通过。没有保留本轮审查提出的未修复问题。

查询计划确认作者月份使用`messages_visible_author_time`的时间范围，按会话日期使用`messages_visible_room_time`，revision使用`message_revisions_account`覆盖索引；未依赖对sent_at文本的时区不安全比较。

Mac只需pull、构建frontend、重启后端，health应为schema11；沿用原数据库和来源服务，无需重新全量同步。云端性能不能代替真实Mac结果。
