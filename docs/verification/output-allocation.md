# 单次输出分配与引用纠正

2026-11-17（北京时间），基线12467b0，schema17不变。

## 两类实际反馈

用户声明上下文1048000、最大输出1000000，上轮把配置最大值直接变成单次814357，触发request_invalid。随后把输出调为8192，请求已能返回，但出现chunk_source_outside_unit。后者是模型返回的引用ID／修订不在当前材料范围，不能再归为接口配置问题；在新诊断运行前不能断言具体是哪一种编号错误。

## 改造

配置是许可上限，单次档案请求先取不超过8192的起始额度，并考虑总窗口。仅在length时可倍增，仍受声明上限和当前完整请求预算限制；格式修复、网络重试与增额共享单次3次和持久unit6次预算，不换unit或清预算。仍不足使用既有分段／字段归纳。若增额被供应商以输出参数拒绝，则记住本次会话已接受额度并返回截断拆分；初始额度本身被拒绝则明确提示模型输出参数。

400／422的max_tokens／max_completion_tokens拒绝按可信参数字段或固定消息特征分类为model_output_limit_rejected，只向界面显示固定文案，不回显供应商原文。未内置猜测某型号的官方最大值，连接最小检查不能证明大输出可用。

引用错误按冻结快照区分未知ID、修订不符和引用其他段，界面只显示计数，不复制聊天、模型原文或猜测式替换编号。对每个unit最多追加一次受限纠正：发送原材料及该段全部合法ID/revision清单，要求完整重返结果；预算容纳不了纠正请求时明确失败。纠正仍绑定原unit／checkpoint，仅更换call_id，继续受累计6次约束。再次失败、空归纳或非法证据不发布，人工覆盖与旧档案不被改写。

没有采用盲拼残缺JSON、放宽引用范围或按姓名匹配消息等做法。供应商实际输出／思考行为和业务语义准确率仍需Mac实测；也没有宣称此次截图的真实引用子类型已经查明。
