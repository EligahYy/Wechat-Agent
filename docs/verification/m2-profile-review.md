# M2任务6—7：档案界面与单客户生产链路

更新：2026-11-16（北京时间）。任务6检查点fe13fae；任务7从该点继续，schema14。本文区分云端实际代码回归与Mac真实业务质量，后者未由合成测试替代。

## 已实现

- 单一客户头部，货品／物流／沟通整卡、人工补充、备货记录和单号编辑；保留日历原文。头像跟随身份标签色，深浅色与改身份即时更新。
- 真实profile/manual/numbers API；409保留填写并显式核对新版本；人工覆盖优先、恢复模型值、重开持久化和单号不改变进度。
- 资料证据从当前已发布快照取得确实被引用的消息／修订与同会话前后最多两条上下文，保留人物／时间／会话；历史修订标注，不扩大当前原文筛选权限。
- 生产RuntimeSession冻结账号和配置版本，worker完成来源同步后刷新活动、识别待识别群发言者的需求，再仅整理业务范围内已确认商家。单客户操作不分析其他商家；已确认身份者不重复跑需求分类。
- WorkflowV1→统一网关→事实校验→稳定批次→事务发布。停止、身份／人工版本／历史修订冲突阻止旧结果覆盖；仅追加消息可发布冻结结果并保持待更新。
- 每次同步先读取真实来源；未变化的输入跳过模型。模型、模板、人工约束、人物、修订、来源变化会使旧输入不再复用。来源读取失败不能当成没有新消息。
- 模型失败保留旧档案；来源与分析状态分开。已发布但有缺口显示“资料已更新，仍有整理缺口”，不冒充全历史或业务语义完整。

## 运行门槛

保存配置不调用模型，最小连接检查与文本预算核对分开。新增`POST /api/model/budget-review`，要求明确true、当前配置版本及无凭据的HTTPS文档依据；JSON Schema模式还需单独确认该格式支持。记录绑定账号与不可变配置版本，修改配置后失效。

预算依据是操作者对供应商文档的人工核对，不是容量压测；capacity_verified／vision_verified保持false。生产只能使用独立检查已通过且预算已有核对记录的配置，图片理解不自动启用。错误预算可能被供应商拒绝；网关仍有本地估算／安全余量／输出上限、有限重试和错误保护，不静默截断。声明值本身不会自动启用运行。

当前一次工作流只处理能装入预算的完整小历史；超窗明确返回context_requires_chunking，保留原文与旧资料，M3再接分段与附件解析。全局操作仍串行、有停止能力，不代表M4每日调度或完整恢复已交付。

## 独立审查与收尾（2026-11-16）

同一最终审查因额度中断后续审原固定提交范围，未对修复另派重审。五项重点未发现新增核心逻辑阻断：混群材料保留实际说话人与目标范围；非法／截断输出、超时与限流受有界网关保护；局部坏引用不抹掉全客户；停止、身份／人工／原文冲突阻止迟到发布；标签互斥、稳定批次与单号不改进度保持。真实混群语义准确率仍须Mac样本验证。

两处Important已用新增回归先复现再修复：

1. 并发编辑返回409后，原实现只换基准版本，没有展示同字段的服务端新值。现在逐项展示“最新资料／我的填写”，重叠修改须明确选择后才能保存；非重叠修改合并进新基准。单号核对保留最新单号与进度，选择采用最新值后无变化不写入，取消不覆盖；恢复模型值也遵循冲突选择。
2. 旧批次保留后，最新概览不再引用其消息会导致来源404。现在先检查当前概览或可见备货记录的引用，再按该批次实际发布过的完整payload匹配历史发布快照。精确修订与账号限制保留，历史消息修订标注；不再可见的旧引用及未引用的上下文仍拒绝读取。

定向回归5后端／7浏览器通过；补充恢复模型、采用最新字段、隐藏历史引用权限后，最终全后端499、全浏览器66、单元31、Node24.14.1构建、wheel、链接／锚点及diff检查通过。wheel逐字节核对当前evidence修复、runtime、runner、budget及014迁移；前次496／61保留为历史记录。

保留Minor：仅人工修改沟通标签时，当前展示尚缺逐标签人工来源和沟通字段模型差异提示。底层人工优先及数据保存正确，来源呈现另行优化。本轮没有混入其他样式改造。

本次实施取舍：

- 证据读取冻结快照及有限同会话上下文，保证结论当时的版本；代价是可能不同于当前日历原文，已标明历史修订。
- 预算启用依赖操作者的供应商文档核对记录，绝不冒充实测；错误核对可能导致供应商拒绝，网关仍失败保留旧资料。
- Mac真实微信／供应商／业务质量门槛保持未验收；当前云端代码交付不替代该门槛，扩大付费使用前须单客户核对。
- 超窗分段、媒体、调度与完整恢复仍属M3/M4，当前相应流程仍不可用。
