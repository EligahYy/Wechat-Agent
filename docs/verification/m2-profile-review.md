# M2任务6—7：档案界面与单客户生产链路

2026-11-15（北京时间）。任务6检查点fe13fae；任务7从该点继续，schema14。本文区分云端实际代码回归与Mac真实业务质量，后者未由合成测试替代。

## 已实现

- 单一客户头部，货品／物流／沟通整卡、人工补充、备货记录和单号编辑；保留日历原文。头像跟随身份标签色，深浅色与改身份即时更新。
- 真实profile/manual/numbers API；409保留填写并显式核对新版本；人工覆盖优先、恢复模型值、重开持久化和单号不改变进度。
- 资料证据从当前已发布快照取得确实被引用的消息／修订与同会话前后最多两条上下文，保留人物／时间／会话；历史修订标注，不扩大当前原文筛选权限。
- 生产RuntimeSession冻结账号和配置版本，worker完成来源同步后刷新活动、识别待识别群发言者的需求，再仅整理业务范围内已确认商家。单客户操作不分析其他商家；已确认身份者不重复跑需求分类。
- WorkflowV1→统一网关→事实校验→稳定批次→事务发布。停止、身份／人工版本／历史修订冲突阻止旧结果覆盖；仅追加消息可发布冻结结果并保持待更新。
- 每次同步先读取真实来源；未变化的输入跳过模型。模型、模板、人工约束、人物、修订、来源变化会使旧输入不再复用。来源读取失败不能当成没有新消息。
- 模型失败保留旧档案；来源与分析状态分开。已发布但有缺口显示“资料已更新，仍有整理缺口”，不冒充全历史或业务语义完整。

## 运行门槛

保存配置不调用模型，最小连接检查与文本预算核对分开。新增`POST /api/model/budget-review`，要求明确true、当前配置版本及无凭据的HTTPS文档依据；JSON Schema模式还需单独确认该格式支持。记录绑定账号与不可变配置版本，修改配置后失效。

预算依据是操作者对供应商文档的人工核对，不是容量压测；capacity_verified／vision_verified保持false。生产只能使用独立检查已通过且预算已有核对记录的配置，图片理解不自动启用。错误预算可能被供应商拒绝；网关仍有本地估算／安全余量／输出上限、有限重试和错误保护，不静默截断。声明值本身不会自动启用运行。

当前一次工作流只处理能装入预算的完整小历史；超窗明确返回context_requires_chunking，保留原文与旧资料，M3再接分段与附件解析。全局操作仍串行、有停止能力，不代表M4每日调度或完整恢复已交付。
