# 整理可靠性 v3 交付记录

2026-11-18（北京时间）。生产整理策略为 `workflow-v3`，本地数据库自动从 schema 17 升级到 18。旧档案和检查点保留。策略切换后第一次整理会生成新的策略检查点。

| 任务 | 本版行为 |
| --- | --- |
| 1. 耗时与基准 | 用单调时钟记录同步、准备、提取、归纳、重试等待和发布耗时。模型调用表保留每次请求耗时、已知用量与出错类型。操作详情显示阶段总耗时和请求次数。 |
| 2. 问题分类 | 资料接口保留 `issues`，新增 `issues_detail`。附件合并计数，数值、单位、日期校验有独立原因。业务未确认与字段证据错误分别显示，编号缺口仍允许已验证消息整理。 |
| 3. 动态组装 | 请求按会话与月份安排，分段只带可见角色、会话、主消息和必要前文。初始输出额度按材料估算。启用稀疏字段输出和可选主材料回执，覆盖最终由程序校验。低负载成功的反馈用于扩大新窗口，超时与截断用于缩小新窗口。已经规划的窗口保留原目标，便于重试复用。 |
| 4. 引用隔离 | 段内短引用可还原为原编号与修订，片段证据按实际可见的字符校验。引用纠正仍只允许一次，如仍有非法引用则移除受影响字段，保留其他验证通过的字段。整段无有效证据和已知越权来源继续拒绝。 |
| 5. 分层归纳 | 大候选组可分开归纳，程序校验每个候选的值与来源是否保留，并记录候选及归纳结果。货品、物流或沟通冲突可保留多条可核对的证据。无法缩到字段容量、无法证明候选保留或超出拆分深度时保留旧资料，显示具体原因。 |
| 6. 继续与缓存 | 每个执行段最多 20 次模型请求或 10 分钟，到预算时可继续。重复提交同一继续请求返回同一任务。继续会新建执行段并再核对来源，复用可验证结果，单元累计请求数沿用。提取键独立于旧档案版本，按实际分段内容、身份、修订与人工约束复用。 |
| 7. 交互与验收 | 记录中可查看阶段耗时、缺口提示和「继续整理」。合成测试覆盖 1、80、81、1000、10000 条主材料、冲突报价、伪造引用、旧修订、发布后追加消息及暂停恢复。 |

这版按会话月份固定工作窗口，新窗口才使用用量反馈。缓存依赖使用实际请求与主材料清单的摘要，并记录每个检查点阅读过的原文与修订。复用前会再次核对这些依赖。对字段保存上限仍无法容纳的冲突保留输入和旧档案，已正常完成的提取不丢失。模型的极端长历史质量、真实耗时和费用基准仍待本机样本验证。

云端验证通过 671 项后端测试、46 项前端单元测试及生产构建。浏览器全量首轮的其余 76 项通过，修正暂停场景数据量后，最终 4 项长历史专项通过。安装包 116 个运行时文件与源码一致，临时库从 schema 17 启动升级至 18 并保留原数据，生产 HTML、JS 和 CSS 请求通过。

升级时构建前端并重启，健康接口应返回 schema 18。对之前失败的客户重新同步一次。后续遇到预算暂停，从整理记录选择「继续整理」。
