任务1建立账号隔离的SQLite结构、只读健康接口与可注入服务工厂。健康查询不重建丢失的数据库，迁移不提交调用方事务、不修改已发布迁移，也不降级新版本数据库。连接由使用它的线程创建、关闭，不跨线程复用。

任务2补齐第三方wx-cli 0.7.4只读适配与原文归档。每页读取前后检查账号、版本与worker，游标绑定账号、会话、页大小、固定截止时间及末尾排序位置。有效消息按稳定源身份区分；相同正文不同ID保留为不同消息，同ID的变化留存原文修订和偏移时间。人工身份不被元数据刷新覆盖；附件只保存引用，不重置已获取文件状态。

普通聊天缺发送人、稳定ID或字段异常时，原文保存在source_issues，该页有效消息仍可保存，但游标不推进。修复后重读可标记旧问题已解决，原始证据保留。没有稳定ID的记录不能按正文生成伪ID；同样内容的不同观察分开保存。系统事件允许没有人物归属，群标识作为事件主体时也不会建成人物；账号或会话错配的整页直接拒绝归档。

会话租约有效120秒、逐页续租，等锁最多5秒；不同数据库连接／进程不能同时推进同一会话。提交再次检查租约、旧游标、取消状态及generation；源端等待不持数据库写事务。重复游标、重复末页、分页无进展及源端失败有独立缺口。达到页数上限单列为incomplete，不伪装成功或源端故障。程序硬关闭后的操作状态恢复与UI控制由任务4继续完善。

当前采用可追溯优先的重读策略：已完成会话下次从头检查可见历史，以捕获旧消息修订；未完成会话续读已保存窗口，--from-start显式重读开头。来源并不提供固定数据库快照，也无法证明隐藏／删除历史完整，history_complete始终false。单客户范围只能使用来源明确成员或已观察关系，不能声称拿到了未发言成员目录。

测试证据：任务1交付114项；任务2新增34项，30项先失败再通过，另4项是已通过行为的特征验证。覆盖提交失败回滚、跨账号／会话、重复内容与ID、修订与搜索、缺口原文、事件、暂停提交、租约并发、游标异常、旧库升级及报告不含正文／姓名／ID／路径。全套148项、pip依赖检查、wheel迁移及合成HTTP双次同步均通过。当前沙箱的TestClient线程与端口受限，完整HTTP检查在外层云端运行。作者自审，未使用子代理，也未连接用户Mac的微信或付费模型。

本次没有新增Python依赖。验证命令见[Mac指南第10节](../MAC_SETUP.md#10-m1任务2小范围分页归档与重复验证)。UI仍是示例原型，正式同步按钮、角色管理、附件获取与模型处理按后续任务交付。
