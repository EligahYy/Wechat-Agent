任务1建立账号隔离的SQLite结构、只读健康接口与可注入服务工厂。健康查询不重建丢失的数据库，迁移不提交调用方事务、不修改已发布迁移，也不降级新版本数据库。连接由使用它的线程创建、关闭，不跨线程复用。

任务2补齐第三方wx-cli 0.7.4只读适配与原文归档。每页读取前后检查账号、版本与worker，游标绑定账号、会话、页大小、固定截止时间及末尾排序位置。有效消息按稳定源身份区分；相同正文不同ID保留为不同消息，同ID的变化留存原文修订和偏移时间。人工身份不被元数据刷新覆盖；附件只保存引用，不重置已获取文件状态。

普通聊天缺发送人、稳定ID或字段异常时，原文保存在source_issues，该页有效消息仍可保存，但游标不推进。修复后重读可标记旧问题已解决，原始证据保留。没有稳定ID的记录不能按正文生成伪ID；同样内容的不同观察分开保存。系统事件允许没有人物归属，群标识作为事件主体时也不会建成人物；账号或会话错配的整页直接拒绝归档。

会话租约有效120秒、逐页续租，等锁最多5秒；不同数据库连接／进程不能同时推进同一会话。提交再次检查租约、旧游标、取消状态及generation；源端等待不持数据库写事务。重复游标、重复末页、分页无进展及源端失败有独立缺口。达到页数上限单列为incomplete，不伪装成功或源端故障。任务4补齐持久化操作与基础停止；完整恢复语义和UI控制继续按后续任务交付。

当前采用可追溯优先的重读策略：已完成会话下次从头检查可见历史，以捕获旧消息修订；未完成会话续读已保存窗口，--from-start显式重读开头。来源并不提供固定数据库快照，也无法证明隐藏／删除历史完整，history_complete始终false。单客户范围只能使用来源明确成员或已观察关系，不能声称拿到了未发言成员目录。

## 任务3：联系人与身份API

GET /api/contacts按真实联系人归一，每页最多20位；支持备注、昵称、wxid与来源群名搜索，中文单字和字面通配符有回归。本人不进入管理列表。缺失名称明确标记且复制值为空，不用wxid冒充微信名称。最近材料时间取原消息并按时区排序，先聚合每个会话／发送人的最新条目再关联联系人，避免按成员重复展开整段群历史；last_business_at与档案更新时间保持空，未生成模型档案。相关来源缺口继续返回，不被资料状态隐藏。

PATCH /api/contacts/roles只修改明确选择的联系人，校验role_version；同角色不重复增加版本。合法项与冲突项分别返回，409的details中可能包含已成功提交的项；数据库错误则整批回滚。角色变化保留原文，只撤销未开始的analysis工作，不影响来源同步、其他联系人或正在运行的项；后续发布须重验身份和快照版本。

账号由服务端配置或注入来源限定；无配置时只对唯一已归档账号提供离线访问，多账号要求明确绑定。请求中的账号不能自行越权。联系人读取使用同一只读快照保证总数、标签计数与列表一致；读写接口只打开现有数据库，缺失时返回503，避免误建空库。任务3检查点schema为2；任务4新增迁移到3，均无新增依赖。
