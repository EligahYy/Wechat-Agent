任务1建立账号隔离的SQLite结构、只读健康接口与可注入服务工厂。健康查询不重建丢失的数据库，迁移不提交调用方事务、不修改已发布迁移，也不降级新版本数据库。连接由使用它的线程创建、关闭，不跨线程复用。

任务2补齐第三方wx-cli 0.7.4只读适配与原文归档。每页读取前后检查账号、版本与worker，游标绑定账号、会话、页大小、固定截止时间及末尾排序位置。有效消息按稳定源身份区分；相同正文不同ID保留为不同消息，同ID的变化留存原文修订和偏移时间。人工身份不被元数据刷新覆盖；附件只保存引用，不重置已获取文件状态。

普通聊天缺发送人、稳定ID或字段异常时，原文保存在source_issues，该页有效消息仍可保存，但游标不推进。修复后重读可标记旧问题已解决，原始证据保留。没有稳定ID的记录不能按正文生成伪ID；同样内容的不同观察分开保存。系统事件允许没有人物归属，群标识作为事件主体时也不会建成人物；账号或会话错配的整页直接拒绝归档。

会话租约有效120秒、逐页续租，等锁最多5秒；不同数据库连接／进程不能同时推进同一会话。提交再次检查租约、旧游标、取消状态及generation；源端等待不持数据库写事务。重复游标、重复末页、分页无进展及源端失败有独立缺口。达到页数上限单列为incomplete，不伪装成功或源端故障。任务4补齐持久化操作与基础停止；完整恢复语义和UI控制继续按后续任务交付。

当前采用可追溯优先的重读策略：已完成会话下次从头检查可见历史，以捕获旧消息修订；未完成会话续读已保存窗口，--from-start显式重读开头。来源并不提供固定数据库快照，也无法证明隐藏／删除历史完整，history_complete始终false。单客户范围只能使用来源明确成员或已观察关系，不能声称拿到了未发言成员目录。

## 任务3：联系人与身份API

GET /api/contacts按真实联系人归一，每页最多20位；支持备注、昵称、wxid与来源群名搜索，中文单字和字面通配符有回归。本人不进入管理列表。缺失名称明确标记且复制值为空，不用wxid冒充微信名称。最近材料时间取原消息并按时区排序，先聚合每个会话／发送人的最新条目再关联联系人，避免按成员重复展开整段群历史；last_business_at与档案更新时间保持空，未生成模型档案。相关来源缺口继续返回，不被资料状态隐藏。

PATCH /api/contacts/roles只修改明确选择的联系人，校验role_version；同角色不重复增加版本。合法项与冲突项分别返回，409的details中可能包含已成功提交的项；数据库错误则整批回滚。角色变化保留原文，只撤销未开始的analysis工作，不影响来源同步、其他联系人或正在运行的项；后续发布须重验身份和快照版本。

账号由服务端配置或注入来源限定；无配置时只对唯一已归档账号提供离线访问，多账号要求明确绑定。请求中的账号不能自行越权。联系人读取使用同一只读快照保证总数、标签计数与列表一致；读写接口只打开现有数据库，缺失时返回503，避免误建空库。任务3检查点schema为2；任务4新增迁移到3，均无新增依赖。

任务3新增30项测试：初始21项先失败，缺失数据库两项及读快照一致性一项先失败后修复；另6项为已通过行为的特征验证。全套178项、依赖检查、真实HTTP分页／修改／409／403，以及解包wheel后的路由与schema2启动均通过。HTTP测试使用带空格的临时路径和合成联系人，未修改用户真实身份。作者自审，无子代理。Mac只需验证读取与统计，命令见[指南第11节](../MAC_SETUP.md#11-m1任务3联系人api验证)。

## 任务4：持久化同步操作与后台worker

POST /api/operations先写不可变意图再返回202；同账号同幂等键复用同一任务，改变参数明确409，不同键重复同一活动范围也冲突。应用lifespan拥有worker，来源只在有明确任务时延迟构造；领取事务保证同账号不被两个worker同时运行。进度在页提交后持久化，历史查询省略内部checkpoint，详情返回实际source_state、items、options及history_complete=false。

停止先递增generation再取消本进程的在途请求，迟到页不能提交，已经归档的资料保留。正常退出停止活动项；启动发现所有者进程已退出时标记interrupted／stopped，不自动重跑。完整租约、PID复用、继续／重试仍由M4处理，不将基础处理描述成完整无人值守恢复。无效持久化参数明确失败，不让任务永久卡在running或阻塞后续有效任务。

只同步可直接完成；同步并整理对有材料的merchant建立分析项，即使本次无增量也需要首次处理。模型未实现时source成功与总体failed／capability_not_ready分别保留。单客户操作可以归档共享群，但只计划目标客户的分析；非商家可同步原文，不分析。来源错误与材料／页数缺口分别返回source_unavailable或source_incomplete，不解释成没有新消息。

本次新增25项测试：操作测试23项，其中18项先失败再通过、5项为已有行为的特征验证；API验证命令2项先因模块缺失失败再通过。全套203项及依赖检查通过；wheel包含migration003及新模块，独立解包后schema3／路由启动通过。真实loopback HTTP测试使用合成wx-cli与默认来源工厂：首次6条入库，第二次0新增／0修订、6条不变，同键复用且历史共两次任务。两端服务均已关闭，未连接用户微信或付费模型。

作者按用户要求串行开发并自审，无独立子代理审查；无未处理审查项。Mac随后已回传本任务通过：两个会话、11条不变、无缺口，见Mac记录。正式页面与控件由任务5单独交付和验证。

## 任务5：正式React工作台与统一控件

新增React／TypeScript两页应用，工作台接入真实联系人、身份与操作API，设置读取后端账号及能力状态；生产代码不含合成联系人。每页20位、跨页勾选、工作台页签切换清空选择、主导航保留搜索上下文。查询取消过期请求，更新时保留列表，复用稳定行节点；结果高度和选择栏平滑过渡，身份筛选及导航指示器滑动。身份部分409只清除成功项，保留失败项与明确错误。

公共FormField覆盖文字、搜索、多行和时间，使用48px高度／12px圆角／14px字体；Dialog管理焦点、关闭和复合标题，RoleTag统一蓝／紫／绿／琥珀，我方紫色加粗。输入时间支持9:05规范化；时钟面板两列草稿、应用／取消、Escape／外部取消、方向键／Home／End／Tab，分钟自动滚至当前值，面板避开底部。修复Enter后失焦重复保存、鼠标打开面板提前保存草稿，以及键盘Tab失焦漏保存的边界。

深色覆盖html／body／main和全部控件；外观缓存只保存主题字符串用于首屏，实际偏好仍以后端为准。慢速bootstrap复现并修复刷新时浅色闪烁。减少动态效果覆盖CSS和motion组件。设计应用Apple／taste的工作台原则，用户明确不做移动端，未引入营销页hero／照片／评分门槛。

GET／PATCH /api/settings复用既有账号设置表、带expected_version，不改schema3。设置只保存非敏感偏好，不返回模型凭据或发起来源／模型探测；来源状态取真实任务的上次同步证据，不声称当前在线。每日开关与时间可保存，但调度明确待接入。模型档案、编辑与资料状态筛选暂不可用，原文浏览在任务6，不伪造业务摘要。
