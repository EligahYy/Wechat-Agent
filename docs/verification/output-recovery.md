# 输出截断与多次结构化组装修复

2026-11-17（北京时间）。截图中的来源3/3完成，真实失败为output_truncated；不能继续归因于输入上下文不足。

## 根因及改造

此前档案请求硬编码min(8192,配置最大输出)，且只有输入超窗才分段。输入装得下但输出写不完时直接失败。现在使用配置的输出上限；若固定规则、输出及安全余量无法共存，实际额度按可用窗口分配，并为输入留空间，不把整个窗口预留给输出。实际额度在诊断中可见。

提取遇到finish_reason=length后拆小主处理范围，再收集完整AnalysisResult；归纳遇到length后改为字段／批次单元，程序合并成档案。残缺JSON不解析、不按“继续”文本盲接、不当成功缓存，也不会直接发布到界面。

schema17新增单元superseded标识和同账号／快照父子关系。父失败、请求及用量保留；替代前校验子段主处理区间完整覆盖父范围。程序覆盖只计算有替代证明的活跃叶，所有必要单元成功后才发布，旧档案保留。16→17不清原文、档案或检查点，不重置累计请求预算。

已知截断父单元在相同输入重试时直接恢复拆分，成功叶复用，不重复发送必败大请求。普通单元仍累计最多6次网络请求。提取最多3层、单次最多4个子单元、每次客户流程最多8次提取细分；到最小范围仍截断或单字段／批次无法返回时明确失败，避免无限细分付费。存在大量独立会话的父单元可能需后续调整组装策略，不宣称任意规模无上限。

## 诊断与审查

保存实际请求输出额度，以及供应商提供的completion和reasoning整数用量；不保存推理文本或原始错误。usage缺失、null或畸形不再把length误判为格式错误并重复发送修复请求。状态页显示细分次数，展开诊断显示最近输出额度及截断次数。最近成功单元未返回用量时不伪造计数。

独立只读CR提出两项：输出配置可占满窗口；可空usage使截断误判。两者均以失败测试复现并修复。自测还暴露空消息基线遗漏元信息导致过度细分，改用保留元信息的空正文基线、消息数减半与明确子单元／细分界限。前端轮询回归测试改为等待终态渲染，避免仅凭回调已触发就读取尚未提交的React状态。
